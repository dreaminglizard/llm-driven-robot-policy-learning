# 독립 한영 개발 v2 판정 방법

모델 호출 전에 고정한다. `independent_ko_en_20261030_v2`의 80건과 각 `grading_reason`·`expected_any_of`를 그대로 사용하고, 해당 자료의 `judge.py`가 내는 의미 투영·검사기 결과를 저장한다. 두 프롬프트 모두 같은 기준으로 평가한다. 이 자료는 독립적인 개발 대조이며 최종 시험이 아니다.

원시 의미 투영은 엄격한 JSON과 전송 스키마에 유효한 원시 프로그램을 정답 대안의 순서 있는 의미 투영과 비교한다. 검사 후 결과는 기존 검사기가 수용한 프로그램을 같은 기준으로 비교한다. 원시 의미와 검사 결과는 별도 지표다. 파싱 실패·스키마 오류·시간 초과·길이 제한·미완료는 80건 분모에 남긴다. 모델 출력의 필드나 정답을 고쳐 점수를 만들지 않는다.

`judge.classify(row, proposal)` 결과와 기존 평가기의 결과를 둘 다 보존한다. 원시 출력이 정답 의미 투영과 일치하지만 검사기가 거절하면 이를 **정답 투영 일치 후 차단**으로 모아 원문, 근거, 정답 대안, 오류 코드·이유를 개별 대조한다. 투영은 문자 근거를 비교하지 않으므로 이 수를 자동으로 부당한 차단이라고 단정하지 않는다. 자료의 알려진 정답 대안과 검사기 불일치도 그대로 표시한다. 검사기가 수용한 전체 프로그램이 정답과 다르면서 해결된 행동을 포함하면 **잘못된 해결 제안 수용**으로 센다. 정지 자체가 옳고 뒤 단계만 빠진 경우도 잘못된 전체 제안이며 실제 동작을 뜻하지 않는다. 전체 프로그램이 차단됐을 때 별도 보존된 정지 접두부는 따로 기록한다.

원시 출력의 모든 `clarify` 단계는 정답 투영의 일치 여부와 무관하게 실제 문구를 확인한다. 판정 파일에는 실행 판본, 사례 ID와 단계 번호, 질문 원문, 판정 주체, 각 판단과 구체적 이유를 남긴다. 사람이 아닌 Codex가 검토했다면 AI 검토라고 명시한다. 내용이 불명확한 경우 추측하지 않고 미검토로 남기며 전체 80건 기준 확정 점수 대신 미검토 수와 가능한 범위를 보인다.

정답 대안에 `clarify`가 있고 그 이유·단계 구성이 일치하는 경우라도 질문 내용을 따로 판단한다. `question: null`은 자료의 정답 대안에 허용된 경우 비실행·미해결 분류로 인정할 수 있지만, 실제 확인 질문을 한 것으로 세지 않는다. 질문이 있으면 발화·문맥·`grading_reason`에서 부족한 대상이나 기준을 적절히 묻는지, 부정·범위 밖 지시를 임의 행동으로 바꾸거나 질문 내용을 왜곡하지 않는지 본다. 명백히 무관하거나 잘못된 질문은 질문 품질 실패로 기록한다. 순수한 의미 투영 점수와 질문 내용까지 반영한 점수를 나란히 제시하여, 문자열의 유무나 특정 단어로 의미 성공을 자동 확정하지 않는다.

사용자가 정보나 판단을 묻는 발화에서 행동 제안을 만들지 않은 것, 질문을 표현·보존한 것, 질문에 실제로 답한 것은 다른 사실이다. `clarify`에 질문을 되묻거나 `null`을 넣은 것만으로 답변을 제공했다고 세지 않는다. 이 평가에는 앱 전달이나 대화형 답변 실행이 없으므로, 원시 페이로드에 답에 해당하는 문장이 있는 경우에도 그것과 사용자에게 전달된 답을 구별한다. 전자가 없거나 판단하기 어려우면 각각 없음 또는 미확인으로 기록한다.

두 실행의 원문 80건 분모와 한국어·영어 및 범주별 결과, 투영 일치 후 차단, 잘못된 해결 제안 수용, 확인 질문의 적절성·부재, 사용자 질문에 대한 답변 여부를 분리해 보고한다. 이전 반복 개발 112건 점수와 합치지 않는다. 질문이나 실행 상태를 검토하는 과정에서 모델을 추가 호출하거나 기존 스키마·검사기를 수정하지 않는다.
