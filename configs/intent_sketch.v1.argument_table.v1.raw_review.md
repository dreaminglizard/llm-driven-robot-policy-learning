# 원시 의미와 계약을 분리하는 사전 판정 기준

이 기준은 추가 표 대조의 생성 전에 고정한다. 기존 80건의 발화·문맥·정답과 보충 표지를 수정하지 않는다. 같은 기준으로 기존 B와 새 B의 원시 JSON을 사례별로 검토하며, 정답이나 검토 표지를 모델 입력에 넣지 않는다. 기존 응답을 이미 본 검토자가 수행하는 반복 개발 분석이다.

- **원시 전체 의미**는 발화의 요청·부정·정정·질문과 작업 순서, 명시된 대상·수량·높이·반복 조건·참조를 모두 보존했는지 판정한다. 발화의 지시어는 모델에 전달되지 않은 상태를 모델이 임의 선택하지 않고 지시 의미로 보존했는지 본다. 문맥 결속과 별도 실행 범위 판정은 이 지표에 합치지 않는다.
- 각 원시 JSON의 모든 필드와 발화 근거를 그대로 읽는다. 금지 인자라는 구조 오류만으로 의미까지 틀렸다고 자동 판정하지 않는다. 반대로 원문에 없는 대상·배치를 만들거나 행동을 빼거나 바꾸면 의미 오류다. 잘못된 필드를 지워 완성된 프로그램이나 정답으로 만들지 않는다. 허용되지 않은 필드가 전체 의미를 어떤 방향으로 바꾸는지 판단할 수 없으면 `uncertain`으로 남긴다.
- `correct`, `incorrect`, `uncertain`을 모든 입력에 배정한다. 실제 응답이 없거나 파싱하지 못한 경우는 원시 전체 의미를 표현하지 못한 실패로 분모에 남기고 원인을 따로 기록한다. 확정 정답 수와 미확정 수, 전체 80건 기준 가능한 범위를 함께 보인다.
- 범위 밖 높이·자리와 빠진 대상은 사전 보충 표지로 요청 자체의 보존을 확인한다. 아무 행동도 내지 않음은 안전한 비실행과 관련된 결과일 뿐 원래 요구의 원시 의미를 완전히 보존한 정답으로 자동 처리하지 않는다.
- 원시 판단의 근거는 사례 식별자·검토자·이유·결론으로 남긴다. 두 경로의 기존 자동 채점과 기존 검사기는 수정하지 않는다. 참고로 작업 종류·순서만 비교한 수치를 전체 의미 정답률로 바꾸지 않는다.
- 최종 제안의 기존 기준 일치, 추가 보존 기준, 계약 차단, 기존 검사기 차단, 잘못된 전체 제안에 행동이 들어간 통과 사례를 별도로 센다. 확인 질문의 실제 문구를 모두 읽고 품질과 의미 영향·사용자 질문에 대한 답변 여부를 구분한다. 원시 의미와 질문 판정은 이미 틀린 형식이나 행동을 사후에 고치지 않는다.
