# 한영 명령 해석 개발 자료

이 자료는 `task_program.v2`의 새 **개발용 텍스트 자료**다. 한국어 40건과 영어 40건, 총 80건의 발화·합성 실행 문맥을 모델을 호출하기 전에 작성했다. 최종 시험이나 사람 음성·실물 로봇 시험이 아니다. 기존 최종 보류 자료는 열지 않았다.

[개발 입력과 정답](development80.jsonl)은 각 행에 발화, 실행·반복 상태와 식별자만 담은 `reference_context`, 허용 정답 대안 `expected_any_of`, 판정 이유를 보존한다. 문맥은 실제 실행 로그가 아니다. 복귀 대상의 실제 배치와 경로는 입력에 넣지 않았다. 40개 의미군을 한영으로 구성했으며, 같은 발화와 서로 다른 복귀 초점을 비교하는 통제 사례가 있어서 언어별로 문자열은 36개, `(발화, 문맥)` 입력은 40개다. 원래 문장만 복제한 것이 아니라 정지·반복 경계, 단계 순서, 네 복귀 기준, 현재·직전 참조, 범위 밖 대상과 질문 등을 비교한다. 기존 112건과의 정규화된 정확한 문장 중복은 없지만, 이 결과는 의미상 독립성까지 증명하지 않는다.

원통 ID 5, 자리 5, 3층 요청은 현재 스키마의 범위 밖 대조다. 질문과 인용은 명령 실행으로 바꾸지 않는다. 무음은 발화로 꾸미지 않았으며 이 자료에 포함하지 않았다. 무음·인식 실패의 무호출 검사는 별도 입력 검증 과제다.

기존 v2 평가기의 `load_records`로 읽을 수 있고, 저장된 정답 대안 103개의 의미 투영이 기존 평가기와 일치한다. 교환처럼 순서가 대칭인 작업과 의미상 허용되는 표현은 대안을 분리했다. 자유 형식 질문이 있는 `clarify`는 텍스트 키워드로 정답을 판정하지 않는다. 각 관련 행의 `clarify_requires_return_target_question`은 기존 평가기의 수동 검토 경로를 강제하기 위한 호환 필드다. 이름은 복귀 질문을 가리키지만 이 자료에서는 모든 `clarify`에 적용한다.

기존 평가기는 `question: null`을 자동 정답으로 처리하지 않지만 오답으로 셀 수 있다. [별도 판정 보조](judge.py)의 `classify(row, saved_proposal)`는 문구가 있거나 없는 모든 `clarify`를 `manual_review`로 둔다. 사람은 질문이 실제 불명확한 대상을 묻는지, 질문 없이 비실행 상태로 남겨도 되는지를 확인해야 한다. 구조상 `semantic_match`는 제안 내용의 일치이지 로봇 실행이나 전체 자연어 응답의 성공이 아니다. 이 모듈은 저장된 제안만 분류하며 모델에 요청을 보내지 않는다.

[검증 결과](validation.json)는 스키마·문맥·정답 대안, 기존 평가기 형식과 투영, 수동 질문 검토를 모델 없이 확인했다. 80건 중 76건은 적어도 한 정답을 현재 검사기가 받아들이고, 4건은 모든 정답 대안이 거절된다. 이 차이와 일부 추가 대안의 거절을 결과 파일에 남겼다. 4건의 자연어 의미를 검사기 규칙에 끼워 맞춰 바꾸거나 검사기 성공으로 보고하지 않았다. 이후 평가에서는 원시 제안과 검사 후 결과를 각각 보고 이 차이를 구분한다.

[작성 스크립트](build_dataset.py)와 [검증 스크립트](validate_dataset.py)는 모델·마이크·장치를 호출하지 않는다. 둘 다 기존 출력 파일을 덮어쓰지 않는다. 재실행이 필요하면 기존 자료를 보존하고 새 출력 위치를 사용해야 한다. 검증 파일에는 자료, 현재 해석기·스키마·프롬프트와 기존 개발 자료의 해시가 기록돼 있다.
