# 독립 한영 명령 개발 자료 v2

이 판본은 [독립 정답 검토](../../../docs/2026-10-30_독립_한영명령_개발자료_정답검토.md)를 반영한 모델 호출 전 개발 자료다. [v1 자료](../independent_ko_en_20261030_v1/development80.jsonl)와 그 검증 결과는 보존했다. [v2 자료](development80.jsonl)는 한국어 40건과 영어 40건이며, 최종 시험 자료가 아니다.

`finish_current_no_new_round`의 두 발화는 현재의 개별 작업만 마친 다음 같은 회차의 나머지 작업과 이후 반복을 하지 않는다는 뜻으로 명확히 했다.

- 한국어: “현재 작업 하나만 완료하고 이번 회차의 남은 작업과 이후 반복은 하지 마.”
- 영어: “Finish only the current task; skip the remaining tasks in this round, and do not repeat.”

이 경계는 현재 작업을 마친 직후인 `after_task`다. 같은 회차를 끝까지 마친 뒤인 `after_round`와 다르다. 허용된 정답 대안의 의미는 바꾸지 않았고, 수정된 문장의 근거 구절과 한국어 참조 표현만 새 문장에 맞췄다.

영어 `a cylinder` 사례는 단수 대상을 나타내므로 `count: 1`과 현재 제안 형식의 `count: null`을 모두 유지했다. 명시적인 숫자가 없는 일반 복수 표현과 구별하며, `null`과 `1`이 실제 실행에서 동등한지는 이 자료가 결정하지 않는다. 두 대안 중 `1`은 현재 검사기가 거절하지만 검사기 결과에 맞춰 정답에서 지우지 않았다.

다른 78개 발화, 모든 합성 실행 문맥과 모든 정답의 의미 투영은 v1과 같다. 변경된 두 발화의 판정 이유와 영어 단수 사례의 판정 이유만 함께 정리했다. 같은 표현과 다른 복귀 초점의 통제 사례를 포함하므로 언어별 발화 문자열은 36개이며 `(발화, 문맥)` 입력은 40개다. 범위 밖 자리·높이·원통 ID와 비실행 질문을 포함한다. 무음은 별도 입력 검증 문제이며 문장으로 만들지 않았다.

정답에 `clarify`가 포함되는 22건은 질문 내용이 적절한지 키워드만으로 자동 정답 처리하지 않는다. [판정 보조](judge.py)는 관련 제안을 `manual_review`로 남긴다. 이는 검토 대기 상태의 이름이며, 검토 시에는 실제로 사용한 판정 주체와 식별 정보, 판정 결과 및 그 이유를 기록한다. 아직 판정이 없으면 미검토로 남긴다. 기존 v2 평가기는 `question: null`을 자동 정답으로 처리하지 않지만 오답으로 셀 수 있어 비실행의 적절성과 질문의 적절성은 별도로 검토한다.

[검증 결과](validation.json)는 기존 평가기의 입력과 정답 의미 투영, 스키마, 합성 문맥과 v1 대비 변경 범위를 모델 없이 확인한 기록이다. 현재 검사기는 80건 중 78건에서 적어도 한 정답을 받아들이며, 나머지 2건의 모든 대안과 다른 사례의 일부 대안을 포함해 총 5개 대안을 거절한다. 별도로 정답과 다른 동작 정지나 높이 조건 누락을 검사기가 받아들이는 검토된 반례 4개도 다시 확인했다. 정답 판정 보조는 이 4개를 `semantic_mismatch`로 구분한다. 이 판본에서 정답이나 검사기를 불일치에 맞춰 바꾸지 않았다. 평가 시 원시 제안과 검사 후 결과를 구분한다.

v2 파일의 SHA-256은 `e14fde7bde9e600fde5e54775fcca59ee850f42a2894f710c70a9d864772dd18`이다. [작성](build_dataset.py)과 [검증](validate_dataset.py)은 기존 결과를 덮어쓰지 않으며 모델, 마이크, 장치 또는 새로운 예시 프롬프트를 사용하지 않았다. 보류된 최종 자료도 열지 않았다.
