# 한국어 작업 의도 자료와 평가 경계

> **최신 범위:** 사용자는 문맥에 따른 원위치, 반복 시작·중단, 동작 중단 후 원위치처럼 순차 제어를 추가로 요청했다. 아래 단일 의도 경로와 복합 지시 거부는 이전에 고정한 초기 비교 기준이며, 확장된 최종 명령 계약이나 지원 완료를 뜻하지 않는다. [이중 언어 초기 범위와 미구현 항목](BILINGUAL_BASELINE.md)을 참조한다.

이 자료는 ASR이 이미 출력한 **문장**에 대한 수작업 정답이다. 녹음·마이크·음성 인식률 자료가 아니다. [개발 20문장](development.jsonl)과 [보류 100문장](holdout100.jsonl)을 모델 평가 전에 별도 고정했고, 정확히 같은 문장은 양쪽에 없다. [지문과 개수](manifest.json)는 평가기에도 고정되어 있어 파일 또는 지문을 바꾸면 기존 보류 집합으로 평가하지 않는다.

보류 집합에는 지원 작업뿐 아니라 무음, 부정·복합 지시, 범위 초과, 비활성 원통, 모호한 대상, 행동 가능 여부를 묻는 질문과 지시문 삽입을 포함한다. 상태를 묻는 질문은 별도 `status`다. 정답은 각 JSONL의 `expected`이며, `registered_scene`은 아래쪽부터 쌓은 **현재** 등록 ID다. 이 장면은 모델이 아니라 로컬 검증기에만 전달된다. `null` 장면은 등록이나 기억 등 현재 원통의 위치가 필요하지 않은 사례다.

보류 문장과 결과를 프롬프트·검사기·학습 자료 조정에 사용하지 않는다. 보류 평가를 보고 변경이 필요하면 해당 보류 집합은 이미 노출된 평가로 취급하고, 새로 독립된 평가 집합을 따로 정한다. 이 100문장은 최종 시험이나 실제 사용자 발화의 대표 표본으로 주장하지 않는다.

## 출력 계약

[스키마](../../configs/language_intent.schema.json)의 일곱 필드는 `intent`, `source_slot`, `destination_slot`, `object_id`, `count`, `height`, `registrations`다. 말하지 않은 값은 `null`이고, 자리와 원통 ID는 1~4, 높이는 1~2다. 이동·쌓기는 출발 자리 또는 명시된 원통 ID와 도착 자리가 필요한 단일 원통 제안이다. 교환은 두 자리 전체의 교환 제안이다. 불확실하거나 지원하지 않는 조건을 임의로 채우지 않는다.

`registrations`는 등록 발화에만 사용하며 각 원소는 `{"slot": 자리, "count": 개수, "object_ids": 명시된 ID 배열 또는 null}`이다. 빠진 자리를 빈자리로 채우지 않고, 말하지 않은 ID를 자동 부여하지 않는다. 등록 목록이 `null`이거나 일부 자리만 있으면 등록 절차를 요청한 것이며 전체 장면이나 ID 배정이 완성된 것이 아니다. 자리별 수와 ID 수가 모순되거나 현재 지원하는 단일 이동의 개수·높이와 맞지 않으면 제안을 반환하지 않는다. `remember`, `restore`, `initial`, `stop`, `reject`, `clarify`에는 다른 필드가 없어야 한다. `restore`는 의도만 표시하며 기억한 목표 배치를 프롬프트나 정답에 넣지 않는다.

## 호출과 평가

[인터프리터](../../raccoon_memory/language_intent.py)는 의존성을 주입할 수 있는 OpenAI 호환 chat-completions 클라이언트를 제공한다. 네트워크 통신은 실제 클라이언트의 `complete`를 호출할 때만 발생한다. HTTP 루프백 IP와 `localhost`만 허용하고, `localhost`는 `127.0.0.1`로 고정하며 API 키나 외부 요청은 사용하지 않는다. 리다이렉트도 따라가지 않는다. 서버 주소와 모델 이름은 호출자가 지정한다. 서버가 제공하는 기능을 아직 확정하지 않았으므로 기본값은 프롬프트로 JSON을 요청하는 방식이다. `json_object`와 `json_schema`는 서버 지원이 확인된 뒤 명시적으로 선택한다.

모델에는 고정 시스템 프롬프트와 해당 발화만 보낸다. 정답, 현재 등록 배치, 기억의 목표 배치, 교사 경로나 관절 목표를 보내지 않는다. 모델의 JSON 문법, 스키마, 텍스트 근거와 로컬 장면 조건을 검사하며 잘못된 값을 다른 행동으로 보정하지 않는다. 실패는 명령 없는 오류로 남기고 모델이 직접 `reject` 또는 `clarify`를 제안한 경우에만 그 의도를 반환한다. 정지/Esc의 직접 경로 및 기존 명령기·세션·실행기는 이 코드에 연결하지 않았다.

텍스트 조건 검사는 보수적인 규칙과 모델 판단의 조합이다. 일반 한국어의 모든 부정·은유·다중 의도를 완벽히 인식한다는 보증이 아니며, 검사를 통과한 제안도 실행 권한이 아니다. 실제 실행 전 별도의 상태 확인·안전 검증과 기존 직접 정지 경로가 필요하다.

[평가기](../../scripts/evaluate_language_intent.py)는 사용자에게서 서버 주소와 모델 이름이 주어진 뒤 실행할 수 있다. 출력 경로는 항상 새 폴더여야 한다. 예를 들어 다음 명령의 주소와 모델 이름을 준비된 서버 값으로 바꾼다.

```powershell
python scripts/evaluate_language_intent.py --split development --base-url "http://127.0.0.1:8080/v1" --model "LOCAL_MODEL" --output "artifacts/language_intent/development_run_01"
```

각 사례의 원본 응답·검사 실패·예측과 `results.jsonl` 및 `report.json`에 다음을 별도로 남긴다.

- 엄격한 JSON 문법 성공률과 스키마 성공률: 모델 호출 수 기준. 무음은 호출 전에 차단하므로 분모에 넣지 않는다.
- 의미 정확도: 원시 JSON의 정답 일치와 검사 후 제안의 정답 일치를 전체 문장 기준으로 따로 센다. 원시 정답률은 실제 모델 호출을 시도한 문장 기준으로도 기록한다. 양방향 자리 교환과 등록 목록 순서는 같은 의미로 처리한다. 타임아웃·잘못된 JSON·무음 차단도 전체 문장 기준 정확도 분모에는 남긴다. 원시 답이 정답과 같더라도 검증에 실패하면 검사 후 정답으로 세지 않는다.
- 원시 응답에 나타난 잘못된 작업 제안과 검사를 통과해 남은 잘못된 작업 제안: 따로 센다. `reject`와 `clarify`를 기대한 사례가 실제로 비실행 상태로 남은 수도 별도 기록한다. 오류로 차단된 결과를 올바른 `reject` 답변으로 바꿔 세지 않는다.

잘못된 제안 수는 정답 필드를 엄격하게 비교하는 보수적 지표다. 예를 들어 단일 이동의 `count=1`을 `null`로 출력해도 별도의 안전한 일치 판정 없이 불일치로 센다. 이는 실제로 잘못된 동작이 발생했다는 측정이 아니다.

개발 문장에 대한 로컬 Gemma 실행과 모의 검사 결과는 [개발 평가 보고서](../../artifacts/language_intent/20261030_gemma4_e2b_dev20_schema_v3/DEVELOPMENT_REPORT.md)에 있다. 개발 문장으로 프롬프트와 스키마를 보완한 결과이므로 일반화 성능이 아니다. 보류 100문장에 대한 모델 평가와 실제 마이크·실물 실행 결과는 아직 없다.
